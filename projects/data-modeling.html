03 / CASE STUDY

Power BI Dimensional Modeling & Data Integration

Integrated data from multiple business processes and organized it into a multi-fact data model using Power Query, shared dimensions, relationships, and DAX measures.

GitHub Repository ↗

Project objective

The project focused on combining related business data into a structured Power BI model that supports analysis across sales, customers, products, inventory, campaigns, promotions, order processes, and sales targets. The emphasis was on the model design and relationships rather than dashboard styling.

Dataset overview

PLATFORMPower BI
TRANSFORMATIONPower Query
MODEL TYPEMulti-fact dimensional model
REPORTINGDAX measures

The source tables cover multiple related business processes, including customers, products, orders, inventory, campaigns, invoices, payments, shipments, sales targets, and geographical information.

Data preparation & transformation

Data integration & cleaning

  • Merged and appended related source tables.
  • Removed unnecessary columns and redundant fields.
  • Created index-based keys where required for relationships.
  • Combined order information with relevant shipment, invoice, and payment-date fields to represent stages of the order lifecycle.

Data restructuring

  • Unpivoted inventory data to represent product values by period.
  • Split the promoted product SKU list into individual rows, creating separate campaign–product associations.
  • Organized transformed data into fact and dimension tables.
  • Mapped campaign names and product SKUs to their corresponding campaign and product keys using the dimension tables.
  • Mapped bill-to city and ship-to city values to geographical keys using the geography table.

Data model design

Fact tables

Fact tables represent different business processes and metrics at their respective levels of detail.

Key modeling concepts

Multi-fact modeling: Organizing multiple fact tables within a single model.
Shared dimensions: Connecting related business processes through common dimensions.
Data granularity: Understanding what each fact-table row represents.
Role-playing geography: Representing bill-to and ship-to locations with geography relationships.
Campaign–product associations: Using campaign and product keys to represent which products are linked to each campaign.
Relationship management: Working with keys, cardinality, and filter paths between tables.

DAX & reporting

Created basic DAX measures and KPI cards for total orders and total sales. A summary table and visuals were used to validate the relationships between integrated tables and check whether key totals remained consistent. The report was created primarily to verify the data model, rather than as a fully developed interactive dashboard.
